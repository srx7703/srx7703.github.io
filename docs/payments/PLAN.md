## 0. 一句话结论

"新支付"不是一个行业，而是四门赚钱方式不同的生意：收单、企业卡、BNPL、跨境。同样经手 100 美元，留下的钱从约 0.16 美元（Adyen）到约 4.15 美元（Affirm，已扣坏账和资金成本）不等，差约 26 倍 [C]。所以"市场份额"只能在同一门生意里、按写明的口径来算。

展开说三点。

**区别：看每 100 美元谁拿走多少。**
- 收单赚费率差价。
- 企业卡赚刷卡回佣（interchange，扣掉返现），再加客户资金的利息。
- BNPL 本质是放贷。Affirm 六成以上的收入来自利息和卖贷款 [C]。
- 跨境赚汇差、手续费和余额利息。

**份额：每个赛道能做到的程度不一样。**
- BNPL 是唯一有官方、免费、口径统一份额表的赛道。美联储 FEDS Note（2026-06-05）给出 2025 年美国六家主要机构共发放 1,567 亿美元，其中 Afterpay/Block 占 34%，Affirm 26%，PayPal 17%，Klarna 15% [V]。
  - 两份草稿都漏了这张表，还因为 Block 不单独披露而把 Afterpay 排除在份额之外。实际上它排第一。
- 收单没有这样的表，只能用三把尺子量：披露流水、网站覆盖、开发者下载。三把尺子的结果互相打架，打架本身就是发现：
  - Stripe 在开发者下载里占八到九成，在五家披露流水池里只占约三成 [C]。
  - 在美国前 1 万网站里，Stripe 已经超过 PayPal：2026-08 移动端 origin 数为 522 对 478 [V，今天实测]。
  - 在全部美国网站里，仍是 PayPal 领先。
- 企业卡和跨境没有免费的全市场分母，只做"披露者池内排名"，私营公司给区间。

**2025–26 年整合很快，所以"是否独立"必须是数据里的一个字段。**
- Capital One 收购 Brex，2026-04-07 完成 [V]。
- Global Payments 完成 Worldpay 收购，2026-01-12 [V]。
- Mastercard 完成 BVNK 收购，2026-08-03 [V]。
- Nuvei 宣布收购 Payoneer，2026-06-15，预计 2027 年中完成 [V]。
- Stripe 宣布收购 OpenRouter（2026-08-19）和 Parafin（2026-09-30）[V]。

## 1. 研究范围

### 1.1 分赛道与公司清单

按主要收入来源归层，不按功能清单。一家公司跨几层时，归到它最大的收入来源那一层。

| 赛道 | 靠什么赚钱 | 核心公司（进图、进份额） | 只进分类表 | 基准 |
|---|---|---|---|---|
| A 商户收单 | 费率差价 + 软件 | Stripe、Adyen、Checkout.com、PayPal（含 Braintree）、Block/Square、Shopify Payments、Toast、Fiserv Clover、Global Payments+Worldpay、Shift4 | Rapyd、Highnote | Visa、Mastercard（只当轨道和费率表来源） |
| B BNPL | 放贷（利息、卖贷款）+ 商户费 | Affirm、Klarna、**Afterpay（Block）**、PayPal Pay Later、Zip、Sezzle | — | 美联储 BNPL 表 |
| C 企业卡、支出管理、企业银行 | 回佣减返现 + 客户资金利息 + 软件 | Ramp、Brex（属 Capital One）、BILL、Navan、Mercury、**Corpay（新增，上市的传统企业支付基准）** | Rippling、Expensify、AvidXchange（2025-10-15 被 TPG 和 Corpay 私有化 [S]） | Amex 商务卡 |
| D 跨境 B2B 与资金管理 | 汇差、手续费、余额利息 | Airwallex、Wise、Payoneer（待被收购）、dLocal、Flywire | Ebury、Nium | FSB 跨境成本指标 |
| E 发卡基础设施（对照组） | 按交易分成 | Marqeta | Lithic、Unit | — |
| F 稳定币（对照组，不算份额） | 储备金利息 | Circle | Bridge、Tempo、BVNK | Stripe 估计 2025 年全市场稳定币支付约 4,000 亿美元 [V] |

两个归层的特殊情况：
- Navan 约 91% 的收入来自差旅预订 [C，输入为 S]，在表里标为"归 C 层，但收入以差旅为主"。
- Mercury 主要靠存款利息。

### 1.2 不做什么

- 中国、印度、消费类新银行、加密交易所、汇款公司，都留到 v2。
- 不做估值推荐。
- 不用任何付费数据。

### 1.3 时间和地域

- 财务数据：最近 8 个季度，全部对齐到日历季度。Affirm、BILL 和 Zip 的财年 6 月结束，Wise 3 月结束，Navan 1 月结束。
- 网站覆盖：从 2020-01 开始。
- 事件：从 2025-01 开始。
- 地域以美国为主。全球公司用它自己的全球口径，并在图上标注。

## 3. 方法

**M1 分层地图，再看产品线收敛。**
- 做一张"公司 × 9 条产品线"的矩阵。9 条线是：收单、结账钱包、BNPL、企业卡与费用、应付、多币种与外汇、发卡基础设施、银行与资金管理、稳定币。
- 每格记四件事：状态（在卖 / 通过合作方 / 已宣布 / 已停）、上线日期、来源、`last_checked`。
- 有了上线日期，就能画"每家卖几条产品线，2020 到 2026 年怎么变"。这样可以检验"大家都在变成中小企业财务操作系统"这个行业说法，把"都是干啥的"从描述变成一个趋势。

**M2 每 100 美元的四本账。**

瀑布的每一步存成一行：谁付、谁收、金额、依据、来源、标签。没有披露的步骤用区间。

| 生意 | 账怎么算 |
|---|---|
| 收单 | 商户付 3.20 美元（Stripe 标价 2.9% + 0.30 [V]）。其中发卡行拿 2.14 美元（Visa Traditional Rewards 线上档，2.04% + 0.10 [V]）。卡组织费 [U]。收单方毛差约 0.90 美元 [C] |
| 企业卡 | 毛回佣 2.80 美元，减去返现约 1.32 美元，净约 1.28 美元 [C] |
| BNPL | Affirm FY26 扣除交易成本后留下 4.15 美元 [C] |
| 跨境 | FSB 统计的行业均价 1.6%，对比 Wise 0.52% 和 Airwallex 约 0.45% [C] |

另附一张"指标词典"。每个比率都写清在哪些公司之间可比：总 take rate、净 take rate、利润型留存（Affirm 的 RLTC、Klarna 的 TMD、PayPal 的 TM$）、扣返现后的回佣率、存款利息收益率。

**M3 份额：四把尺子。**

(a) 披露者池份额
- 用公司自己披露的流水算，只在同一层、同一口径、同一期间里比。
- 一律标"池内份额"。集中度指标（HHI）也只在池内算。

(b) 官方分母份额
- BNPL 直接用美联储 FEDS Note 的六家表 [V]。这六家在池内的 HHI 约 2,400 [C]。
- 要注明两点：这张表是六家之和，不是全市场；部分公司的美国数字是按全球数缩放估出来的。
- 收单只用美联储支付研究和 Census 电商数据当上限分母，只给区间。

(c) 网站覆盖
- 数据来自 HTTP Archive。一律叫"覆盖"，不叫份额。
- 每次附一张检测覆盖表，摊开盲区：Adyen 全球只在 69 个 origin 上检测到，Square 只有 51 个。

(d) 开发者下载
- 数据来自 npm。包名白名单要预注册，因为结果对白名单很敏感（同样算 Stripe，份额在 84% 到 90% 之间变动）。
- 服务端和客户端分开算，用指数化后的趋势看。

规则：跨层不相加；口径不匹配就给区间或者不画；年化数不和过去十二个月（TTM）的数混用。

**M4 私营公司：给区间，不给点。**
- 建一张"披露台账"，每条公开碎片一行。数字带限定符（= / > / < / ~），而且限定符要在计算中传下去：分子带 ">"，结果就是下限。
- 来源按可靠程度排序：
  1. 公司自己说的；
  2. 交易对手的文件，例如 Capital One 10-Q 里的 Brex 收购价分摊；
  3. 子公司的法定报表；
  4. 用同层上市公司的费率夹出区间，例如 Stripe 净收入按流水的 0.30–0.45% 算，约 57–86 亿美元 [C]，属于假设；
  5. 第三方估算，只用来展示分歧，不当输入。
- Stripe 的爱尔兰控股公司 Stripe Payments International Holdings 2025 年营业额 67.9 亿美元，销售成本 53 亿美元，覆盖欧洲、中东、非洲和亚太（EMEA+APAC）[V，RTE 2026-09-23]。坊间流传的"Stripe 营收"序列每年都和它吻合，但它是这一个区域实体的毛营业额，含转付给发卡行的 interchange，毛利约 22% [C]。所以那个序列既不是集团口径，也不是净收入。页面上写成"有界推断"，并承认也可能是第三方本来就拿这个实体的数字作代理。

**M5 敏感性矩阵。**
- 对四本账施加同一组冲击：利率 ±100 bp、坏账 ±50%、interchange −10 bp、返现比例 +10 个百分点、商户拒收 10% 的商务卡。
- 输出每种冲击下，每 100 美元留存变化多少。读出来就是"每种模式押的是哪种风险"。

**M6 收入结构拆分。**
- 从 10-K 和 20-F 的收入分项里整理，每家公司画一条 100% 堆叠条。
- 例如：BILL 拆成订阅、交易、float；Affirm 拆成商户、卡网络、利息、卖贷款、服务；Wise 拆成手续费和利息（Wise FY26 客户余额利息收入 8.061 亿美元 [V]）。

**M7 辅助信号（不进份额）。**
- 招聘：13 家公司的公开职位板，从现在开始每周快照，只存岗位数。
- Form D 监控：私营公司的融资额。
- 2025–26 事件时间线。

| FSB、美联储支付研究、FRED（汇率、SOFR、电商）、ECB、BIS | 分母 | 可用。Census API 要 key，改从 FRED 取 | 能 |
| HTTP Archive Tech Report API | 网站覆盖，2020-01 起 | 今天实测可用 | 能。维护者 2026-09-21 表示鼓励复用，署名不强制 [V] |
| npm 下载 API | 开发者下载 | 今天实测：`stripe` 包 9 月下载 8,591 万次，`@adyen/api-library` 108 万次 [V] | 只存计数 |
| 招聘职位板（Greenhouse、Ashby） | 招聘 | 13 家可用，只有当前快照，没有历史 | 只存计数，不存职位描述 |
| PyPI | 补充 | 几次请求就 429，只保留 180 天 | 计数 |

**不用的来源：**
- Google Trends：非官方接口返回 429，官方 API 还在 alpha。
- Common Crawl 索引：返回 504。
- 自建爬虫：命中率低，还会撞上反爬。不绕过反爬，只用来抽小样本校验检测规则。
- Yahoo / yfinance：自己写明仅限个人使用。
- Similarweb、Crunchbase、PitchBook、Nilson、Statista、Sacra 付费部分、Bloomberg 付费墙：付费或不能再分发。
- Apple iTunes lookup：条款属于灰色地带，默认不用。
- Tranco 名单：不进仓库。

**已知缺口：** 美国商务卡的全市场总量、收单的全市场份额，都没有免费来源。

## 6. 怎么上 portfolio 网站

**名称**
- slug 建议用 `payments-landscape`。
- 标题建议："Who keeps what: what new payments companies sell, move and keep"。

**管线 `pipelines/payments/`**
- 模块：
  - config：公司、包名、职位板的白名单，全部钉死 ID；
  - reference、economics、ledger、share、webtech、devstats、jobs、formd；
  - publish：带回退保护，如果一次运行丢了一半公司，就不覆盖上一版；
  - schema（pandera）、evaluate、tests。
- 复用现有代码：
  - `pipelines/sec`：先修上面说的两处；
  - valuation 的财年对齐和汇率模块：新增 EUR、AUD、BRL；
  - `common/curation.py`：私营公司数字的存储规则；
  - `share.py`：把分子改成可以选收入、净收入或流水。

**数据流**
1. 手录的数字只写一次，放在 reference JSON 里。每行带 URL、日期、metric_kind、company_confirmed。
2. 校验后写进 facts。
3. MDX 用表达式引用。
4. 测试保证两件事：正文里没有手打的数字；页面上每个私营公司数字都能追溯到一行可信的记录。

**自动更新 vs 手工整理**
- 每周自动更新：SEC 财务、Form D、FRED、HTTP Archive（数据本身按月）、npm、招聘岗位数。
- 手工整理，按季度或有事件时更新：流水和 GMV、私营公司数字、费率表（一年两版）、产品矩阵、事件。
- 整理过的数据超过 90 天没复查，页面上置灰。

**v0 的 7 张图**
1. 分层地图加产品线收敛（点阵图）。
2. 主图：流水 × 收入的双对数散点，配 0.1%、0.3%、1%、3%、10% 五条等留存率斜线。实心点是文件里的数，空心点是公司自述的年化数。Stripe 只有流水，所以画成一条区间竖线。
3. 四本 100 美元的账（瀑布图）。未披露的步骤画成浅灰色区间。
4. 同赛道份额小多图，分四面：BNPL（美联储表）、中小商户 POS（GPV）、企业级收单池、跨境池。每一面都写明口径和期间。
5. 私营公司区间图：Stripe 净收入、Ramp 收入除以采购额、Brex 卡消费、Checkout.com 费率。
6. 敏感性点阵。
7. 2025–26 事件时间线：上市、并购、定价融资三类。

v1 再加两张：三口径对照的哑铃图（对应 Q1、Q2）；网站覆盖的月度趋势，附检测覆盖表。

**页面其余部分**
- 三项关键数字（默认）：每 100 美元留存的跨度（约 26 倍）；BNPL 第一名的份额（Afterpay/Block 34%，来自美联储）；Stripe 2025 年自述流水 1.9 万亿美元。
- 表格：公司矩阵、指标词典、私营公司台账、没进图的公司及原因、检测覆盖表。
- 附录：Method、Evaluation（H 节）、Data quality、Sources and data rights、Build notes（分开写 AI 做了什么、你决定了什么）、Changelog。
- 页首写明："只用公开数据，不构成投资建议。"
- 版式：不做卡片，不用品牌色，所有图遵守 CHART_RULES。

## 6.5 交互看板

**形态。** 网站的设计规范要求页面读起来像研究笔记，不能做成卡片墙或仪表盘产品。所以每个看板都是同一个结构：
- 一行筛选器；
- 下面 2–3 张联动的图；
- 再下面一张可搜索、可下载的表。

不用卡片、彩色标签或小方块。

**技术。**
- 现有的 `VegaChart` 已经支持图内交互：悬停、点选高亮、Vega-Lite 下拉绑定。
- 一排筛选器同时控制几张图，需要新加一个小组件 `DashboardControls`。筛选器一变，就通过 Vega 的 `view.signal` 同时更新同一看板里的所有图，并沿用 `FilterBar` 的逻辑同步过滤下面的表。
- 筛选状态写进网址，例如 `?segment=bnpl&company=affirm`，方便直接分享某个视图。
- 手机上筛选器自动折行，图竖排。
- 不支持的组合直接用一句话说明原因，不显示空图。例如："企业卡赛道没有官方分母，所以没有官方分母份额。"

**四个看板：**

1. **公司对比（Company explorer）**
   - 筛选：赛道；公司（可多选高亮）；指标（流水、收入、每 100 美元留存、同比增速、利润率、Rule of 40）；期间（季度或 TTM）。
   - 图：
     - 所选指标的季度序列。所选公司用颜色标出，同赛道其他公司用灰色作背景。
     - 流水 × 收入的双对数散点，配等留存率斜线。点选一家公司，左图同步高亮。
   - 表：最新一季的数字和出处链接。
   - 更新：SEC 财务每周自动更新；流水和 GMV 来自手工整理的 KPI 台账，每个财报季更新。
2. **份额（Share lens）**
   - 筛选：赛道；口径（披露者池 / 官方分母 / 网站覆盖 / 开发者下载）；期间。
   - 图：
     - 所选口径下的份额条形图。
     - 同一家公司在不同口径下份额的哑铃图。这张图直接对应 Q1、Q2，口径之间打架本身就是发现。
   - 表：分母是什么、来源、期间、是否"池内份额"。
3. **采用与开发者信号（Adoption tracker）**
   - 筛选：公司；网站排名段（前 1 万、前 10 万、全部美国网站）；设备（移动或桌面）；包的类别（服务端或客户端）。
   - 图：
     - HTTP Archive 月度网站覆盖趋势；
     - npm 周下载指数化趋势；
     - 公开职位板的岗位数，按职能分。
   - 附一张"检测覆盖表"，写明哪些公司测不准，例如 Adyen、Square。
   - 更新：每周自动。
4. **私营公司台账（Private ledger）**
   - 筛选：公司；数字类型（公司自述的年化数、融资估值、交易对手文件、推断）；是否公司确认。
   - 图：
     - 区间图。每个数字画成一个区间，带 > 的是下限。
     - 估值和并购事件时间线。
   - 表：每条公开碎片一行，带链接、日期和限定符。
   - 更新：手工整理，超过 90 天没复查就置灰。

**另外两处：**
- 页面开头保留规范要求的 3 个关键数字。
- 预注册问题记分板（Q1–Q9，每题标"收集中 / 成立 / 被推翻 / 无法裁决"）做成一张表，放在看板之前。

## 6.6 正文里的"数据处理方法"一节

这一节放在结果之后、附录之前，标题定为 "How the data is built"。附录里的 Method 只留技术细节和链接。

1. **数据流程图。** 从左到右：数据源 → 原始层（只追加，不改历史）→ 快照 → 指标表 → facts → 页面。每个箭头上写这一步做了什么。图由代码生成，不手画。
2. **每个数据源一小段：抓什么、多久抓一次、怎么清洗、已知偏差。**
   - **SEC 财务**：
     - 从 companyfacts 拆出季度数，第四季度 = 全年 − 前三季；
     - 再算 TTM，并按各家财年对齐到日历季度；
     - companyfacts 滞后时回退到 frames 接口；
     - 写清楚 20-F 和 IFRS 公司（Klarna、Wise）怎么处理。
   - **KPI 台账**：
     - 流水和 GMV 从 8-K 正文里解析；
     - 每个数字都带口径字段；
     - 限定符（>、~）在计算中往下传。
   - **网站覆盖（HTTP Archive）**：
     - 检测规则来自 Wappalyzer，统计单位是 origin；
     - 解释为什么只叫"覆盖"不叫"份额"，以及 Adyen、Square 为什么几乎测不到；
     - 趋势用 3 个月滚动平均。
   - **开发者下载（npm）**：
     - 包名白名单（预注册时定死）；
     - 服务端和客户端分开算；
     - 自动构建（CI）会把下载量放大，所以只看指数化后的趋势。
   - **招聘**：每周快照，去重，只存岗位数，按职位名称归到职能的规则写明。
   - **私营公司**：怎么把零散的公开数字变成区间，比如 Stripe 净收入按同层上市公司的费率夹出范围。
3. **指标词典。** 每个指标写清公式、单位、可以在哪些公司之间比、不能在哪些公司之间比。做成可筛选的表。
4. **数据质量。** 每次运行都会自动检查缺失、数值范围、重复、是否过期、异常跳变，结果直接显示在页面上（复用 `DataQuality` 组件）。
5. **可复现。**
   - 代码链接；
   - 重跑整条管线的命令；
   - 可下载的数据，只放能公开的部分。
6. **局限清单。** 哪些结论只是"方向性"的，以及原因。

**工期**：两节合计约 2–3 天。主要花在新组件 `DashboardControls`（联动、网址记状态、手机适配、测试）和流程图生成上。

## 7. 核验规则

1. 2025–26 年的事实每一条都重开原页核对，日期取页面正文。只有 [V]，以及完全由 [V] 输入算出的 [C]，才能进 facts。[S] 必须升级或降级，[U] 不上图。
2. 每个数字带七个字段：URL、发布日、截至日、口径定义、metric_kind（封闭词表）、是否公司确认、最后核对日。
3. 口径跟着数字走：TPV、GPV、GMV、处理量、年化采购量不能互换。年化数不和 TTM 混用。期间对不上就打 `period_mismatch` 标记。
4. 份额只在同层、同口径、同期间内算。跨层不相加。"池内份额"必须标出来。
5. 来源冲突时不取平均，而是并列记录。例如：
   - Ramp 收入：公司说"超过 10 亿美元"，Bloomberg 说"超过 15 亿美元"；
   - Worldpay 完成日：8-K 写 01-12，草稿写的 01-09 有误；
   - Airwallex 融资稿的日期：页面写 06-25，有草稿写成 06-26；
   - Wise 年报的日期：页面写 06-26，草稿写成 06-25。
6. 所有权状态单独成字段：独立、已被收购、收购待完成，附日期。
7. 包名、职位板 token 全部钉死，并核实归属。已知的同名坑：npm 的 `affirm`、PyPI 的 `affirm` 和 `airwallex`、Greenhouse 的 `wise`，都不是这几家公司本身。
8. 新鲜度检查：
   - companyfacts 和 submissions 比对，滞后就回退到 frames；
   - 整理过的数据超过 90 天没复查就置灰；
   - HTTP Archive 出现异常跳变就报警；
   - 职位数单周掉超过 50% 就报警。
9. 预注册先于数据。之后的任何修改写进"修订"小节，不改原文。
10. 隐私：
    - SEC 联系方式只从 secret 读。
    - 页面上不放任何个人信息。

## 9. 风险

- **口径错配导致排名错误。** 这是最大的风险。应对：第 7 节的第 3、4 条规则，加上图上的口径标签和检测覆盖表。
- **私营公司选择性披露。** 只在对自己有利时才公布数字，所以台账天然偏乐观。应对：公司自述的数只当下限，用空心标记，画区间。
- **推断出错。** Brex 的卡消费依赖回款周期的假设；8.15 亿美元是公允价值，不是面值；部分应收款可能在合作银行的账上；Stripe 爱尔兰实体那条也可能另有解释。应对：写成有界推断，列出全部假设，接受更正。
- **事实变化快。** 一年里有 4 起以上并购，Ramp 在谈新一轮，和解听证会在 11-16。应对：状态字段、90 天置灰、按事件更新。
- **网站检测有偏差。** 应对：永远叫"覆盖"，附检测覆盖表。可以顺手向上游提交检测规则的修正，这本身就是一个作品集亮点。
- **开发者下载被 CI 放大，或者对白名单敏感。** 应对：预注册白名单，只看指数化后的趋势。
- **数据权利。** 应对：`.gitignore` 加评审清单，不用任何 vendor 数据。
- **合规与利益冲突。** 应对：只用公开信息；页面写明不构成投资建议；发布前由作者确认适用的对外发布政策。
- **范围膨胀。** 应对：定量部分只做约 25 家核心公司。
- **外部接口变化。** HTTP Archive 的接口不是正式公开的 API；SEC 有每秒 10 次的访问限制。应对：每个数据源单独失败、互不影响，再加回退保护，阻止一次失败的运行覆盖上周的数据。
- **利率依赖。** 资金利息类的数字随利率变化。应对：所有这类比较都标日期。
